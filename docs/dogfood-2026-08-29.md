# Dogfood run — 2026-08-29

First run against a real, unfamiliar Python codebase: a 449-test suite in a
private lead-generation engine (47 test files).

## What happened

| | |
|---|---|
| Tests discovered | **449** |
| Static pass runtime | **1.6 s** |
| Full probe run | **timed out at 10 minutes** |
| Findings, first run | 3 FAKE (`A3-test-constructed-only`) |
| Findings, after the fix | **0** |
| False positives found | **3 of 3** |

## Finding 1 — A3 was unsound, and the dogfood proved it

All three FAKE verdicts were wrong, and all three were the same pattern. Shown
here as an equivalent reconstruction — the analysed repository is private, so no
source from it is reproduced:

```python
seen = []                       # "test-constructed", says the origin tracker

def sink(value):
    seen.append(value)          # ...but PRODUCTION code is what fills it

process(items, sink=sink)
assert seen == [1, 3]
```

A container created empty in the test, handed to production code through a
callback, mutated by it, then asserted on. The origin tracker sees `[]` and
says *test-constructed*; it does not model mutation through a closure.

The three real cases, described rather than quoted:

- a crawler test whose spy list is filled by the function under test
- a scheduler test whose spy list is filled by the run loop
- an architectural guard that scans the repository's own sources for a banned
  API call and asserts the offender list is empty — it can absolutely fail

The pattern is preserved as a permanent fixture in
`test/corpus/python/tricky/test_looks_fake_but_real.py`, so the regression
cannot come back.

**Fix:** A3's claim is *"production code never reached"*, so it now stands down
whenever the test body contains any production call at all, and emits a probe
obligation instead. Tracking aliasing properly is where static analysis goes to
die; declining to accuse is free.

Regression tests: `test/core/triage.test.ts`, "A3 stands down when production
code ran" and "A3 still fires when genuinely no production code runs".

## Finding 2 — the probe does not scale yet

`cover` is one pytest invocation, then each mutant is another. At ~449 tests
that is well past ten minutes. **Known limitation, not yet fixed.** The static
pass is 1.6 s, which is why `--static` now exists.

The honest framing: `--static` buys speed by giving up certainty, never by
giving up honesty. Everything it cannot prove stays `UNKNOWN`, so a `--static`
run can never report clean — as this one did not:

```
no fake tests among the 0 I could vouch for; 449 I could not (449 not-analyzed)
```

Options for later: run probes concurrently, reuse one pytest process across
mutants, or probe only tests changed in a diff.

## Finding 3 — the honesty gate works on real data

The gate never claimed clean at any point in this exercise, including when the
findings list was empty. That is the whole design working: an empty findings
list and a clean bill of health are different statements, and only one of them
was earned.

## Finding 4 — a false positive in greenrot's own test suite

While fixing the above, the perf regression test was found to assert only
elapsed time:

```ts
assert.ok(ms < 8000);   // an error path returning in 4ms passes this
```

That is a B7 "asserts nothing about behaviour" test, in greenrot's own suite.
It now asserts the outcome as well. Noted because it is exactly the class of
defect this tool exists to find, and it got in anyway.
